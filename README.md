# B站广告片段跳过

一个运行在 Microsoft Edge 里的 B 站广告辅助工具。它会根据字幕、B 站原生弹幕和你自己维护的产品词，找出视频里比较像广告的片段并直接跳过；跳转后底部会出现“回到跳转前”按钮，点一下即可恢复。

> **这是开发中的版本，识别还不完美。**
>
> 漏掉广告、把正常内容当成广告、空降时间识别错误，都属于当前阶段需要解决的问题。你提交的每一条纠错都会用于改进规则。反馈越多、纠正越具体，后续识别就会越准确。

## 它现在能做什么

- 读取 B 站视频字幕，按产品词识别广告。
- 没有命中产品名时，根据“好消息、推荐、优惠券、质保、购买链接”等连续语境识别常见商单。
- 读取 B 站原生弹幕，识别 `空降8:16`、`八一六`、`八分十六` 等跳转提示，优先级高于本地规则识别。
- 在悬浮窗中提前显示所有空降候选，并标明“可选 / 已过 / 超出视频”。
- 识别到广告后直接跳转，不打断播放节奏。
- 跳转后可一键“回到跳转前”；同一片段不会反复触发。
- 支持导入 JSON 规则包，用关键词、必含词、排除词和正则补充内置规则的漏判。
- 可选接入 DeepSeek 或其他 OpenAI 兼容模型，让 AI 辅助判断广告的起止范围。

vCaptions 不是必需依赖。扩展直接读取 B 站字幕和弹幕；vCaptions 可以让字幕列表、翻译和点击字幕界面更完整。

## 安装

1. 打开 `edge://extensions`。
2. 打开右侧的“开发人员模式”。
3. 点击“加载解压缩的扩展”。
4. 选择这个项目里的 `dist` 文件夹。
5. 打开任意 B 站页面。页面侧边中央会出现一个粉色圆形“跳”按钮。
6. 点击圆形按钮展开悬浮窗，在“设置”里添加产品词。

如果修改了源码，需要先运行：

```powershell
npm install
npm run build
```

然后在 `edge://extensions` 点击扩展卡片上的“重新加载”，再刷新 B 站页面。

## 第一次使用

1. 登录 B 站。大多数视频需要登录后才能读取字幕。
2. 在悬浮窗的“设置”页添加你希望识别的产品词，一行一个。
3. 打开视频并等待悬浮窗显示“字幕已就绪”或“等待字幕”。
4. 播放到广告片段时，扩展会直接跳转，底部出现“回到跳转前”按钮。

悬浮窗包含四个栏目：

- **状态**：当前视频、识别到的片段数、空降时间候选、AI 状态。
- **设置**：产品词、通用商单检测、弹幕识别、片段边界和自定义规则入口。
- **AI**：DeepSeek/OpenAI 配置。
- **日志**：字幕、弹幕、AI、跳转和错误记录。

点击浏览器工具栏里的扩展图标，可以显示或隐藏悬浮窗。

## 空降时间怎么处理

扩展会从 B 站原生 XML 弹幕里寻找跳转提示，例如：

- `空降8:16`
- `跳到八分十六秒`
- `八一六`
- `一零三零`
- `空降816`

识别结果会提前列在悬浮窗里。**弹幕提示的优先级高于规则识别**：空降弹幕刚从屏幕上飘过时（带“空降 / 跳到”等明确语境，或同一目标被多条弹幕重复），只要目标时间仍晚于当前播放位置，就会直接跳到该时间，即使这一段没有命中产品词或商单语境。多个目标时采用排序最靠前的那个。

如果同一时刻也落在规则识别出的广告片段内，仍然优先使用弹幕给出的时间；弹幕没有给出可用目标时，才回落到规则识别的自动跳过。所有跳转都不会暂停视频，跳转后同样可以“回到跳转前”。把“识别弹幕空降时间”关掉，就会完全回到纯规则识别。

会排除 `1`、`11`、`111`、`一一一`、`666`、`2333` 等观众态度或梗数字，也不会把少于 10 秒的目标当成空降时间。

“好漫长的10分钟”“五分钟”“才过去不到3分钟”等描述剧情时长的句子不会被当成跳转时间。只有带“空降 / 跳到”等明确语境时，才解析 `X分钟`、`X分Y秒`、`X点Y分`；`8:16` 和 `八一六` 仍可独立识别。

## 自定义识别规则（可选）

内置规则覆盖不到的情况，可以在设置页导入 JSON 规则包。规则只在本机执行，不联网。

```json
{
  "version": 1,
  "name": "我的规则包",
  "rules": [
    {
      "name": "3C 数码商单",
      "keywords": ["旗舰店", "到手价", "以旧换新"],
      "required": ["优惠券", "下单"],
      "exclude": ["抽奖"],
      "pattern": "",
      "minHits": 2,
      "beforeSeconds": 1,
      "afterSeconds": 2
    }
  ]
}
```

- `keywords`：任一命中就是候选句，按字面包含匹配，忽略空格和大小写。
- `required`：从第一句命中到最后一句命中之间，这段字幕必须全部出现的词；用来排除“只顺口提一次品牌”的正常内容。
- `exclude`：出现这些词的句子不参与命中，比如抽奖、转发。
- `pattern`：可选正则，不区分大小写，和 `keywords` 是“或”的关系。
- `minHits`：至少多少句命中才算一个片段，默认 1。
- `beforeSeconds` / `afterSeconds`：片段前后缓冲秒数，默认 0.5 / 1.5。

导入时会逐条校验，正则写错会直接指出是哪条规则。导入后点击“保存设置”生效，正在播放的视频会自动重新分析。示例文件见 `examples/rules.example.json`。

## AI 识别（可选）

本地规则不需要 AI。若启用 AI，默认使用 DeepSeek：

- 服务商：DeepSeek
- API 地址：`https://api.deepseek.com/v1`
- 模型：`deepseek-chat`
- API Key：填写你自己的 Key

AI 只接收视频标题、时长和带时间的字幕文本，不发送音频或产品词。它负责返回疑似广告的起止字幕编号，扩展再把编号转换成时间并使用原有的跳转与“回到跳转前”功能。API 调用可能产生费用。

如果 AI 返回“没有广告”或空数组，扩展会按无结果处理；如果返回内容无法解析，日志会显示模型响应的开头，方便排查。

## 为什么会出现漏判和误判

视频广告的表达方式并不固定：

- 同一段广告可能只提一次产品名。
- 中间可能长时间只讲使用体验，不再出现产品名。
- 弹幕可能用缩写、错别字、谐音或 `八一六` 这样的数字写法。
- 正常评测、新闻和剧情里也可能出现产品词或价格。

所以当前版本一定会有漏判和误判。请不要只反馈“没用”，尽量附上具体视频、时间范围、当时看到的字幕或弹幕，以及悬浮窗日志。定位越具体，修正规则后对其他视频的帮助也越大。

欢迎通过以下方式反馈：

- 提交 Issue：<https://github.com/YasmineTing/bilibili-ad-skipper/issues>
- 说明是“漏判”还是“误判”
- 附上 B 站视频链接和时间点
- 附上悬浮窗日志或截图

**你纠正得越多，这个项目就会识别得越准确。**

## 隐私和限制

完整的数据流向、权限用途和 AI 外发内容见 [PRIVACY.md](./PRIVACY.md)。

- 本地产品词、弹幕和规则匹配都在浏览器中完成。
- 只有启用 AI 时，视频标题和字幕才会发送到你配置的模型接口。
- API Key 保存在当前 Edge 扩展的本地存储中。
- 首版主要支持 B 站普通视频和分 P，不支持直播、番剧播放器或平台插播广告。
- 只存在于 vCaptions 服务中、B 站接口无法读取的字幕，扩展也无法分析。

## 开发和测试

```powershell
npm run typecheck
npm test
npm run build
$env:EDGE_PATH = "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe"
npm run test:e2e
```

项目使用 TypeScript、Vite 和 Manifest V3。测试覆盖字幕片段合并、AI 返回解析、弹幕时间解析、空降候选过滤、悬浮窗交互、自定义规则、自动跳过、回到跳转前和分 P 切换。

`dist` 是构建产物，不要手动修改。提交前运行 `npm run verify`（类型检查 + 单元测试 + 构建）；推送后 CI 会重新构建并校验 `dist` 与源码是否一致，不一致会直接失败。
